# 라우팅과 페이지 레이아웃

React Router Data 모드 사용. `Router.tsx`에서 URL·페이지·레이아웃을 등록하고 `paths.ts`의 경로 상수와 생성 함수를 사용한다.

`Router.tsx`는 이동·지연 로딩 보조 함수 → 화면별 라우트 그룹 → 최종 라우터 조합 순서로 구성한다. 공간 진입 전 화면은 `entryRoutes`, 기본 탭은 `tabRoutes`, 소식 작성·상세는 `recordRoutes`, 공간 안의 레이아웃 조합은 `spaceRoutes`, 개발 전용 화면은 `developmentRoutes`에서 관리한다. 기존 URL·등록 순서·중첩 레이아웃·제목과 활성 탭 정보는 유지하며, 새 화면은 해당 그룹에 추가한다.

## 경로

| URL                                          | 화면                    | 레이아웃                                     |
| -------------------------------------------- | ----------------------- | -------------------------------------------- |
| `/`                                          | 랜딩                    | 브랜드 소개                                  |
| `/login`                                     | 일반 로그인             | 뒤로가기 헤더                                |
| `/onboarding/guide`                          | 기록 전 안내            | 뒤로가기 헤더 + 계속 버튼                    |
| `/spaces/new`                                | 공간 생성               | 뒤로가기 헤더 + 고정 제출 버튼               |
| `/spaces`                                    | 공간 선택               | 브랜드 헤더                                  |
| `/invitations/:invitationToken`              | 초대 수신·Mock 참여     | 브랜드 헤더 + 소셜 버튼, 하단 탭 없음        |
| `/spaces/:careSpaceId/invite`                | 가족 초대               | 뒤로가기 헤더 + 액션 + 가족 탭               |
| `/spaces/:careSpaceId/home`                  | 홈                      | 공간 전환 헤더 + 소식 작성 액션 + 홈 탭      |
| `/spaces/:careSpaceId/news`                  | 소식 목록               | 공간 헤더 + 작성 액션 + 소식 탭              |
| `/spaces/:careSpaceId/news/new`              | 소식 작성               | 뒤로가기 헤더 + 고정 제출 버튼, 하단 탭 없음 |
| `/spaces/:careSpaceId/news/:recordId`        | 소식 상세·분석 상태     | 뒤로가기 헤더 + 상태별 액션 + 소식 탭        |
| `/spaces/:careSpaceId/care`, `family`, `all` | 후속 화면용 임시 페이지 | 공간 헤더 + 현재 탭                          |
| `/_dev/components`                           | 공통 컴포넌트 갤러리    | 개발 모드 전용                               |

공간 루트(`/spaces/:careSpaceId`)는 홈으로 이동한다. 정적 `new` 경로는 공간/소식 ID로 처리하지 않는다. 경로 생성은 `spacePath`, `spaceInvitePath`, `invitationPath`, `newsCreatePath`, `newsDetailPath`에서 세그먼트를 인코딩한다. 잘못된 경로는 404, 화면 오류는 공통 라우트 오류로 연결한다. 소식 작성·상세 페이지는 진입 시 코드를 로드한다.

## 화면과 상태의 경계

- `components/`: 표현·레이아웃. 라우트나 도메인에 직접 의존하지 않고 props로 동작 주입.
- `features/carespace/`: 공간 이름·가족·생성 폼·공간 메뉴·초대 안내 UI와 명시적 Mock 메모리 데이터. `careSpaceViewTypes`는 화면 모델이며 BE DTO가 아니다.
- `features/carespace/model/useMockInvitationLink.ts`: Mock 링크·예시 기한·재발급·복사·공유와 수동 복사 안내 상태 관리. 페이지가 URL 생성과 라우트 상태 변경 콜백을 주입하고 화면을 조합한다. 공간 ID가 바뀌면 `SpaceInvitePreview`의 key로 링크 상태를 초기화한다.
- `features/dashboard/`: 홈 상태별 조합. 정상·빈 홈·생성/참여 직후·로딩·전체/부분 오류.
- `features/record/model/`: 소식 표시 모델·예시 데이터·공간별 메모리 저장소·작성 및 분석 재시도 훅. 원문은 공백·줄바꿈을 포함해 보존하며 표시용 분석 상태와 분리. BE 응답 DTO가 아님.
- `features/record/ui/`: 목록·작성 폼·상세 조합·원문 카드. 이동 경로는 페이지의 콜백으로 전달.
- 홈 예시 데이터는 `features/dashboard/model/mockHomeData.ts`에서 관리한다. `HomePage`가 현재 공간의 Mock 소식을 넣어 `HomeView`를 전달하고 `HomeContent`는 목록·건수·문구를 표시한다. 최근 소식과 확인 건수는 소식 저장소를 공유하며 돌봄 항목은 기존 예시를 유지한다. API 연결 시 데이터 공급부를 교체하며 `HomeView`는 BE DTO와 구분한다.
- `pages/`: UI 조합, 라우트 상태와 이동 연결. 현재 로그인/공간 흐름은 Mock이며 서버 요청 없음.
- `TabLayout`: URL의 공간과 탭 판독, 공간 메뉴, Outlet context, 공통 하단 조합. 알 수 없는 Mock ID는 공간 선택 안내로 연결.
- `RecordRouteLayout`: 작성·상세의 공간 조회 및 Mock 활성 여부 확인. 공간/소식 ID를 Outlet key에 반영해 이탈 시 폼·시트·진행 중 타이머 정리. 사라진 소식은 목록 복귀 안내.
- `SpaceBottomNavigation`: Router Link를 공통 BottomNav에 주입. 공간 ID를 유지하며 URL로 활성 탭 결정.

홈·가족 초대·소식의 액션·BottomNav는 **하나의 FixedBottomArea** 안에 배치한다. 내부 BottomNav는 static이며 최하단에서만 safe area를 적용한다. ResizeObserver가 실제 높이를 예약하므로 작은 화면과 긴 문구에서도 본문 마지막 항목까지 스크롤할 수 있다. PageLayout은 유동 폭·최대 512px·최소 화면 높이를 유지한다.

모든 제품 화면의 상단은 `PageLayout`에서 **Mock 안내 + 헤더 + 상단 safe area**를 하나로 묶어 `sticky; top: 0`으로 고정한다. 본문 스크롤 중에도 브랜드·뒤로가기·공간 전환 버튼이 유지된다. 문서 스크롤과 기존 `ScrollRestoration`을 사용하며, 상단 높이 변화는 ResizeObserver로 감지해 문서의 `scroll-padding-top`에 반영한다. 공간 메뉴는 본문과 하단 탭 위에 표시하고, 모달은 기존 dialog 최상위 레이어를 사용한다.

공간 메뉴는 헤더 아래 표시하는 disclosure 영역이다. 키보드로 열면 영역에 포커스를 두고 Tab으로 항목을 탐색한다. Escape는 메뉴를 닫고 호출 버튼으로 복귀하며, 영역 밖 클릭·포커스 이동으로도 닫힌다. 전환 실패 시 기존 공간을 유지한다.

## Mock 확인 방법

`lib/mockPreview.ts`의 `isMockPreviewEnabled` 사용. `.env.production`은 현재 `VITE_ENABLE_MOCK_PREVIEW=true`; 로컬 개발은 변수 미지정 시 활성화된다. `false`에서는 이동 핸들러와 Mock 데이터 변경을 차단한다. 인증·접근 권한 가드는 아니다.

- 랜딩 → 로그인 → 안내 → 공간 생성 → 첫 홈.
- 안내의 **Mock 공간 둘러보기** → 공간 선택 → 예시 홈.
- 공간 선택의 **Mock 초대 참여 예시 보기** → `/invitations/mock-family` → 소셜 버튼 → 참여 홈. 반복 진입 시 구성원 중복 추가 없음.
- 홈/가족 → 가족 초대 → 복사 또는 **Mock 초대받은 화면 보기**. 이미 참여한 공간의 소유자/구성원 역할 유지.
- 홈/소식 목록 → **소식 남기기** → 등록 → 분석 중 상세 → 소식 목록. 작성한 공백·줄바꿈과 작성자·등록 시점 유지. 직접 만든 빈 공간도 첫 소식 등록 후 홈과 목록에 같은 소식 표시.
- 소식 목록의 빈 상태·첫 로딩·전체/추가 조회 실패, 작성의 등록 실패, 상세의 분석 상태를 상단에서 선택. 작성 오류 예시의 재등록은 입력을 유지해 정상 등록. 분석 재시도는 소식을 중복 등록하지 않고 기존 소식의 표시 상태만 분석 중으로 변경. 분석 완료를 자동으로 만들거나 입력에서 제안을 생성하지 않음.
- 제안 있음은 미리 준비한 예시 소식에서만 선택 가능. 상태 선택은 화면 예시이며 저장된 소식 상태를 바꾸지 않음. 제안 검토/삭제 버튼은 후속 안내만 표시. 삭제 안내 버튼은 소유자 또는 본인 작성 소식에만 표시하며 실제 권한 검증은 BE 연동 대상.
- 상단 **화면 상태 확인**에서 화면별 상태 선택. `?mockState=`는 표시 검증용이며 인증·권한·업무 상태가 아니다.
- 초대의 만료/사용 불가/참여 오류, 생성 오류, 목록의 빈 상태/로딩/오류, 홈과 공간 메뉴의 오류를 선택해 확인. 오류 화면의 재시도는 정상 Mock 흐름으로 이동한다.

Mock 데이터는 모듈 메모리에서만 유지한다. 새로고침 시 직접 생성/참여한 공간은 초기화되고 기본 예시 공간 두 개로 돌아간다. 사라진 Mock 공간의 직접 주소는 선택 화면으로 돌아갈 수 있는 안내를 제공한다. 발급 화면의 기한은 UI 예시이고 실제 초대 발급·만료 검증은 수행하지 않는다. 기본 예시 공간 링크와 `/invitations/mock-family`는 직접 진입할 수 있으며, 직접 만든 공간의 Mock 링크는 해당 실행 세션에서만 확인할 수 있다.

복사는 Clipboard API 사용. 지원하지 않거나 권한 오류이면 수동 복사 시트를 제공한다. 공유는 사용자가 버튼을 누를 때만 Web Share API를 호출하며, 미지원·실패 시 수동 복사로 안내한다. 공유 취소는 오류로 표시하지 않는다. 공유 문구에도 실제 참여가 아닌 Mock 링크임을 명시한다.

## 뒤로가기·새로고침

`useBackNavigation(fallback)`은 앱 내 관측 이력이 있으면 `navigate(-1)`, 직접 진입·새로고침이면 대체 경로로 replace 이동한다. `App`은 경로별 제목·본문 포커스·스크롤 복원을 담당한다. URL 쿼리의 임의 외부 return URL은 사용하지 않는다.

정적 호스팅은 `index.html` SPA fallback 필요. 현재 Vercel rewrite 유지. 공간 ID는 권한이 아니며 실제 API 연결 시 세션·참여 검증 필요.

- 소식 목록/작성/상세: `230:2805/2922/3008/3036`; 분석 중/제안 없음/실패/등록 실패: `231:3021/3097/3157/3229`; 빈 목록/오류: `236:4099/4171`; 첫 로딩/추가 조회 실패: `310:14107/14168`.
- 소식 기능: REC-01~04, AI 분석 상태·재시도의 UI 표현, PROP-01/02의 진입·표시. 제안 검토/최종 반영·원본 삭제 및 파생 데이터 처리는 후속 범위.
- 기능: SPACE-01~08, DASH-01~05의 화면 표현과 SPACE-11의 기존 안내 연결. 업무 기능 구현 완료를 의미하지 않음.

후속: 실제 OAuth·세션 복귀와 초대 유지, 공간 목록/생성/멤버·초대 발급/검증/참여 API, CSRF·중복 요청·오류 처리, 홈 API 연결. 신규/기존 사용자 자동 목적지와 부모님 동의 기록 절차는 미정. MSW·인증 상태 저장·실제 업무 API 호출은 추가하지 않음.

소식 연동 의존성: 공간별 목록/페이지 조회·등록·상세, 작성자/소유자 권한, 분석 상태/재시도·멱등성·제안 연결, 소식 내용 제한·오류 응답 계약 확인 후 공통 API 계층에 연결. 현재 표시 모델을 BE DTO로 사용하지 않음.
