# 이슈 #10 검증 기록

범위: 라우팅·공통 레이아웃, 랜딩·로그인·기록 전 안내, 공간별 탭 임시 페이지. API 업무 기능과 배포는 제외.

## 환경과 결과

- Node.js 24.21.0 / pnpm 10.18.2, Windows의 headless Edge(Playwright) 사용.
- 각 구현 단계의 `pnpm check` 통과. 최종 `pnpm build` 통과.
- 최초 빌드는 Windows 샌드박스의 Vite 하위 프로세스 실행 제한으로 실패했으며, 동일 명령을 허용된 실행 환경에서 재실행해 통과. 프로젝트 설정 변경 없음.
- 실제 화면과 Figma 대조, 기존 SVG 파일 존재·렌더링·원본 크기 확인. 랜딩 헤더 심볼 약 28.83×28, 비교 화살표 24×24, 로그인 심볼 약 98.84×96, Google 아트워크 20×20, 나머지 아이콘 24×24.
- 랜딩·안내의 320/390/768/1280px 너비, 작은 화면의 200% 글자 확대에서 가로 넘침 없음. 하단 바 높이 재측정 후 마지막 본문까지 스크롤 가능.
- 로그인 320px/200% 글자 확대에서 가로 넘침 없이 버튼 조작 가능.
- 정상 흐름에서 런타임 오류 없음. 지연 로딩 실패는 별도로 주입해 공통 오류 화면과 시작 화면 복구 확인.

자동 브라우저 검증은 로컬 임시 스크립트로 실행했다. 프로젝트에 별도 테스트 러너·브라우저 의존성을 추가하지 않았다. 실제 모바일 기기/Safari, 실제 OAuth·BE 통신, 배포 서버의 fallback은 이번 검증 범위 밖이다.

## 다시 확인하는 순서

```sh
pnpm dev
```

1. `/`에서 랜딩의 제목·사용 예시·소유자 반영 설명 확인. 시작하기와 이미 계정이 있어요 모두 `/login`으로 이동. Tab/Enter로도 이동 가능.
2. `/login`에서 카카오·Google 각각 선택. 1초 로딩 동안 두 버튼 비활성화 후 `/onboarding/guide` 진입. 뒤로가기 후 다시 시도 가능.
3. 로그인 로딩 중 뒤로가기. 1초가 지나도 안내 화면으로 늦게 이동하지 않음.
4. `/onboarding/guide` 직접 진입 또는 새로고침 후 뒤로가기 → `/login`. `/login` 직접 진입 후 뒤로가기 → `/`.
5. 안내 확인하고 계속 → 다음 화면 준비 중 시트. Esc/닫기로 복귀하고 버튼에 포커스 반환. 동의 기록·공간 생성 없음.
6. 시트의 개발용 Mock 공간 보기 → `/spaces` → Mock 공간 1/2 선택. 다섯 탭을 눌러 공간 ID 유지, URL·선택 표시·페이지 제목 일치, 문서 재로드 없는 이동 확인.
7. `/spaces/mock-space-1/news?filter=mine`에서 헤더 공간 선택 → 뒤로가기. 원래 URL과 검색 조건 복원. 긴 랜딩의 스크롤 위치, 브라우저 앞으로 가기 후 헤더 뒤로가기도 복원 확인.
8. `/spaces/mock-space-1` → `/spaces/mock-space-1/home`. 한글·공백·슬래시를 포함한 인코딩 ID도 탭 이동 후 유지.
9. `/missing`, `/spaces/mock-space-1/unknown`에서 404 안내와 시작 화면 복구. 오류 화면에 하단 탭 없음.
10. `/_dev/components`와 기존 `/?preview=components`의 갤러리 확인. 로그인 조합 보기 링크는 `/login`으로 연결.
11. 브라우저 Network/Storage에서 OAuth·API 호출, 인증 쿠키, localStorage 인증 데이터가 생기지 않음. React Router의 스크롤 복원용 sessionStorage는 인증 데이터와 무관.

```sh
pnpm build
pnpm preview
```

프로덕션 미리보기에서는 `/login`의 두 소셜 버튼 비활성화. DOM에서 disabled만 제거해도 핸들러의 환경 검사로 이동 차단. `/_dev/components`는 404이며 기존 preview 쿼리는 랜딩 유지. 개발용 갤러리 코드·Mock 공간 진입 링크 제외. 공간별 URL 직접 진입·새로고침 가능하며 여전히 명시적인 임시 화면만 표시.

## 근거와 남은 의존성

- Figma 직접 조회: `206:744` HM-ON-A01, `206:749` HM-ON-A02, `206:754` HM-ON-A03. 기존 공통 보드 `176:3`에서 구현된 컴포넌트·자산 재사용.
- 확인한 기능: `AUTH-01`, `AUTH-02`, `SPACE-01`, `SPACE-02`, `SPACE-11`. 업무 기능 구현 완료를 의미하지 않음.
- 세션 쿠키·CSRF, OAuth 성공/실패와 복귀 목적지, 사용자 온보딩 상태, 참여 공간 목록·권한, 실제 공간 생성 API 연동 필요.
- 부모님 동의의 절차·증빙·저장 규격, 기존 사용자/여러 공간의 첫 목적지 미정. 안내를 보거나 버튼을 누른 사실을 동의 완료로 처리하지 않음.
- 구성원 요청·소유자 최종 반영 로직은 이번 범위에 추가하지 않음. 랜딩의 반영 예시 문구는 Figma 그대로 유지.
